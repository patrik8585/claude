Custom metadata guide: Insight tab

Account page (HCP and HCO). Attachment to the Change Request "Account Page Redesign". Everything needed to understand and create the records of the Insight tab.

1. How the custom metadata works

Who sees which configuration (selection keys)

Each custom metadata record of the Insight tab has 4 filters. Together they decide which users and accounts the record applies to:

  • Page: HCP page or HCO page.
  • CBU: the country code (e.g. DE, AT). Use DEFAULT for records that apply to every country without its own setup.
  • Team: the user's team (e.g. Adults, Paediatrics). Use Default to apply to all teams.
  • Record type: the account record type. Use Default to apply to all record types.

Only records with Is_Active = true are used.

How the app picks the configuration (resolution)

The app looks for the most specific configuration for the logged-in user and the opened account. It checks the steps below in order and stops at the first step that finds records:

  1. User's CBU + user's Team + account Record type
  2. User's CBU + user's Team
  3. User's CBU + account Record type
  4. User's CBU only
  5. DEFAULT + account Record type
  6. DEFAULT only

The whole configuration always comes from one step. The app never mixes steps: it never takes position 1 from one step and position 2 from another.

2. Creating the records of the Insight tab (Account_Insight_Card__mdt and Account_Insight_Range__mdt)

The Insight tab has three sub-tabs, General (cards), Segment (grid) and Affiliation (table). They are described by two custom metadata types: Account_Insight_Card__mdt (one record for every card, grid column and table column) and Account_Insight_Range__mdt (optional, one record for every colour range). The meaning of each field, the mandatory fields and the display types are in sections 13.4 and 13.5 of the CR.

There are only two custom metadata types to fill: Account_Insight_Card__mdt (one record for every card, grid column and table column) and Account_Insight_Range__mdt (optional, one record for every colour range). The examples below always show all the fields of the type. A dash (—) means the field is left blank because it is optional or does not apply. Team__c and Record_Type__c are filled with Default when the record applies to all teams or all record types. Field API names are examples.

Rules:

  1. A configuration is the complete set of records for one CBU / Team / Record type. The app picks one step (section 1) and uses only its records, so a CBU that differs from DEFAULT needs the whole list, not only the differences.
  2. Create separate records for the HCP page and the HCO page (Page__c).
  3. Create records only for what has to be shown: if a field has no record, it is not displayed.
  4. Fill all the mandatory fields of the record (Mandatory column in sections 13.4 and 13.5 of the CR).
  5. Every Affiliation configuration needs a record for From and for To.
  6. All columns of the Segment grid have the same row fields (Grid_Row_Field_1__c, Grid_Row_Field_2__c).
  7. Ranges are created after the card record, and point to it with Insight_Card__c (the DeveloperName of the card). A range works only for that card record.
  8. To switch something off without losing it, untick Is_Active__c.

2.0 Naming convention of the records

Every record of both types has a Label and a DeveloperName. The DeveloperName is the unique name of the record and, for a card, it is also the key that Account_Insight_Range__mdt uses to point to it. In the examples of this guide, the title of each column is the DeveloperName of the record. Because every CBU and team creates its own card records, the naming convention below is mandatory and the same for everybody.

Card record (Account_Insight_Card__mdt)

DeveloperName = PAGE_CBU_TEAM_RT_SUB_Name, six parts separated by one underscore:

PartValueRule
PAGEHCP or HCOSame as Page__c.
CBUCountry code in capitals, e.g. DE, AT. DEF for DEFAULTSame as CBU__c.
TEAMTeam code from the table below. DEF for DefaultSame as Team__c.
RTRecord type code from the table below. DEF for DefaultSame as Record_Type__c.
SUBGEN = General, SEG = Segment, AFF = AffiliationSame as Sub_Tab__c.
NameShort name of the card or column in PascalCase, no underscores, maximum 14 charactersUnique inside the same first five parts. Use the same name for the same card in every configuration (e.g. BabiesPerYear).

The first five parts are at most 22 characters, so the whole name stays within the 40 characters allowed, even with the range suffix. Examples: HCP_DE_DEF_DEF_GEN_BabiesPerYear (HCP page, DE, all teams, all record types, General); HCP_AT_PAE_DEF_SEG_NOB (HCP page, AT, Paediatrics, Segment column NOB); HCP_DEF_DEF_DEF_AFF_From (DEFAULT, Affiliation column From).

Range record (Account_Insight_Range__mdt)

DeveloperName = DeveloperName of the card + _ + number of the range (1 to 10). Example: HCP_DE_DEF_DEF_GEN_BabiesPerYear_1, HCP_DE_DEF_DEF_GEN_BabiesPerYear_2. The number is the order in which you create the ranges of that card.

Label

The Label is always equal to the DeveloperName, for cards and for ranges (for example HCP_DE_DEF_DEF_GEN_BabiesPerYear). The Label has a maximum of 40 characters, like the DeveloperName, so the same name always fits.

Codes of teams and record types

The codes are kept in this table. When a new team or record type is created, add its code here before creating the records. A code has 3 or 4 capital letters, and it is never reused for another team or record type.

How a range points to a card

  • Insight_Card__c is a metadata relationship to the card record. In the range record you select the card, and the DeveloperName of the card is what is stored.
  • Create the card record first and the ranges after.
  • A range belongs to one card record only. If the same card is used in several configurations (for example DEFAULT, DE and AT), every card record needs its own ranges. When you copy a card to another configuration, copy its ranges too and point them to the new card.
  • Do not rename a card record after the ranges have been created: they point to its name.

2.2 Segment: grid (Sub_Tab__c = Segment)

The grid has one record per column: here NOB, CL and Segment letter. The rows are the Account Segment records of the opened account, one row per record. The two row fields say how each row is named: Grid_Row_Field_1__c (mandatory) and Grid_Row_Field_2__c (optional, shown as a chip). They are chosen per configuration (CBU, Team, Record type), so the same grid can be by Therapeutic Area, by Team, or by Therapeutic Area and Team. Rows are sorted by the first row field and then by the second. Use the same row fields on all the column records of a configuration. The three cases below show all the fields of the records. Segment letter has Editable__c = No, so it is read-only. The order of the CL steps (1 to 5) and of the letters (D to A) is the order of the picklist values on the field.
