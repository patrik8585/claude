Change request description · mockup v24. Parts marked New or Changed were added or changed after the business review.

13. Insight tab Changed

The Insight tab has 3 sub-tabs, in this order: General, Segment, Affiliation. The Insight tab contains only what each CBU can configure with custom metadata; the fixed content (Questionnaire, Sample) has its own tabs (items 14 and 15). The Related sub-tab was removed and is not included in the estimation and final design.

  • General, Segment and Affiliation are driven by the same two custom metadata types, Account_Insight_Card__mdt (always) and Account_Insight_Range__mdt (optional colours), with the same selection keys and the same 6-step resolution (see 13.4, 13.5 and the configuration guide in 13.6). The layout is decided by the sub-tab: General = cards, Segment = grid, Affiliation = table.

13.1 General

Sub-tab with the Account fields shown as visual cards (switch, number, date, text, continuum, doughnut; see 13.4.1), with colour ranges. Editable cards have a pencil / Clear; a switch is edited directly. Cards and their order are driven by Account_Insight_Card__mdt (Sub_Tab__c = General) and Account_Insight_Range__mdt.

13.2 Segment

Sub-tab with the Account Segment records of the account, shown as a grid: rows by Therapeutic Area and/or Team depending on the CBU, NOB / CL / Segment letter columns with descriptions, inline edit. NOB and CL are editable inline; Segment letter is read-only New. Columns are driven by Account_Insight_Card__mdt (Sub_Tab__c = Segment, one record per column) and Account_Insight_Range__mdt.

13.3 Affiliation New

Shows the affiliations of the account, between HCP and HCP and between HCP and HCO: all the affiliation records where the opened account is From or To.

The sub-tab is a table. Each column is one record of Account_Insight_Card__mdt with Sub_Tab__c = Affiliation. A column is shown only if it has a record: which columns, in which order, and whether they can be edited is decided per CBU, Team and Record type, with the same 6-step resolution as item 3.

13.6 Configuration guide: how to create the records

There are only two custom metadata types to fill: Account_Insight_Card__mdt (one record for every card, grid column and table column) and Account_Insight_Range__mdt (optional, one record for every colour range). The examples below always show all the fields of the type. A dash (—) means the field is left blank because it does not apply. Field API names are examples.

Rules:

  1. A configuration is the complete set of records for one CBU / Team / Record type. The app picks one step (item 3) and uses only its records, so a CBU that differs from DEFAULT needs the whole list, not only the differences.
  2. Create separate records for the HCP page and the HCO page (Page__c).
  3. Create records only for what has to be shown: if a field has no record, it is not displayed.
  4. Every Affiliation configuration needs a record for From and for To.
  5. All columns of the Segment grid have the same row fields (Grid_Row_Field_1__c, Grid_Row_Field_2__c).
  6. Ranges are created after the card record, and point to it.
  7. To switch something off without losing it, untick Is_Active__c.

Explanation of custom metadata

Who sees which configuration (selection keys)

Each custom metadata record has 4 filters. Together they decide which users and accounts the record applies to:

  • Page: HCP page or HCO page.
  • CBU: the country code (e.g. DE, AT). Use DEFAULT for records that apply to every country without its own setup.
  • Team: the user's team (e.g. Adults, Paediatrics). Leave it empty to apply to all teams.
  • Record type: the account record type. Leave it empty to apply to all record types.

Only records with Is_Active = true are used.

How the app picks the configuration (resolution)

The app looks for the most specific configuration for the logged-in user and the opened account. It checks the steps below in order and stops at the first step that finds records:

  1. User's CBU + user's Team + account Record type
  2. User's CBU + user's Team
  3. User's CBU + account Record type
  4. User's CBU only
  5. DEFAULT + account Record type
  6. DEFAULT only

The whole configuration always comes from one step. The app never mixes steps: it never takes position 1 from one step and position 2 from another.

Open points to confirm New

  1. Source objects for Affiliation, Questionnaire and Sample: affiliation object, questionnaire assignment object, and where the product sample limit and delivered quantity are stored.
  2. Decision maker: editable by the rep on every affiliation. Confirm the field-level security and whether changes on Hard affiliations need an audit trail.
  3. Sample period: the limit is annual. Does the year mean the calendar year, or a fiscal year?
  4. Plan a call: does the calendar create a Pitcher call or a calendar event?
  5. Questionnaire Start: confirm it opens the existing Pitcher questionnaire, and whether mandatory ones must block anything (for example the call).
  6. Questionnaire and Sample tabs on HCO: both are shown on both pages. Confirm they are needed on HCO.
  7. Tab bar: HCP has 6 tabs and HCO 7. The business first asked for Questionnaire inside Insight: confirm the separate tab, and that the bar scrolls well on iPad.
  8. Affiliation columns: which columns does the business want per CBU and Team (Decision maker, Relationship type, Role, Start date, …)? Are the extra ones read-only, or editable (Editable__c)?
  9. Account Segment and Affiliation objects: the link to the opened account is taken from the object of the sub-tab. Confirm Account Segment has a single lookup to Account. For Affiliation both From and To point to Account, and the sub-tab shows the records where the opened account is either of them.
  10. Ranges: From and To limits are both included and ranges of the same record must not overlap. Confirm this rule.
  11. Default colours when no range is defined (13.5.1): confirm with the business.
  12. Card groups: General shows a single list of cards in the order of Sort_Order__c, without section titles. Confirm the business does not need groups.
  13. Affiliation Soft / Hard: who creates Hard affiliations (integration, back office)? In the mockup users create only Soft ones.
