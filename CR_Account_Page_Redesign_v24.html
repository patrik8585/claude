Account Page Redesign (HCP and HCO)

Change request description. Reference mockup: Account_Page_Redesign_Mockup_v24.

Macro requirement

1. Account page layout

Account page layout (HCP and HCO) with a fixed highlight panel and tab bar, single vertical scroll, Pitcher top bar and left menu unchanged.

2. Highlight panel, lines 1 and 2

Highlight panel with name, Target chip, Consent chip, Start call and actions button on line 1, plus fixed fields defined by the global team on line 2:

  • HCP: Workplace, Address, Specialty, Last call
  • HCO: Address, WorkPlace Type, Last call, XX – 4th field to be decided by global team

The list of the second line is also saved in the custom metadata for easy maintenance.

3. Highlight panel, line 3 (custom metadata)

Highlight panel line 3 with 4 fields driven by custom metadata per Country, Team and Record type (with fallback to DEFAULT).

Custom metadata Account_Header_Field__mdt (used for line 2 and line 3):

Resolution for line 3:

CBU + Team + Record type → CBU + Team → CBU + Record type → CBU → DEFAULT + Record type → DEFAULT

4. Target chip

Target chip with engagement plan popover per channel (Goal / Actual / Planned, progress bars, Touchpoints / CEQ toggle).

5. Consent Status chip

Consent Status chip (green / red) with popover showing channel-level consent detail and link to Consent Management History; removal of the current consent and last call banners.

6. Last call field

Last call field with Last Call Details popover (call time, brands, products, TA, channel, pre-call and post-call notes) – same information as-is.

7. Actions button

Actions button ("•••") next to Start call opening the context features, in this order:

  1. Share box
  2. Plan a call – opens the calendar, where the user picks a day and a free slot to plan a call with the HCP/HCO.
  3. Open in Salesforce (online) – always the last option.

8. New tab structure

  • HCP = Summary 360 / Timeline 360 / Details / Insight / Questionnaire / Sample
  • HCO = HCPs / Summary 360 / Timeline 360 / Details / Insight / Questionnaire / Sample

Removal of current toggles and Details sub-tabs.

9. Summary 360 tab rework

Basic info without fields already in the panel, full-width sections, anchor bar, engagement plan link in Last Visit Summary. The Summary 360 tab shows the new 360 page for CDP and non-CDP countries.

10. Timeline 360 tab

Timeline 360 tab (moved out of Summary 360): activities grouped by month, filters (6/12 months, TA, HCP for HCO, activity type, only my activities), call details and attendees for Calls saved in pitcher. This is the rework of the Last Activity Summary that is currently in the new 360 page.

11. Details tab rework

Left navigation with sections and related lists (with counts), search by field name or value, Hide empty toggle, edit button for editing the information of the account.

12. HCPs tab on the HCO page

Renamed from Contacts, same content.

13. Insight tab

The Insight tab has 3 sub-tabs, in this order: General, Segment, Affiliation. The Insight tab contains only what each CBU can configure with custom metadata.

  • General, Segment and Affiliation are driven by the same two custom metadata types, Account_Insight_Card__mdt (always) and Account_Insight_Range__mdt (optional colours), with the same selection keys and the same 6-step resolution (see 13.4 and 13.5, and the attached Insight tab guide). The layout is decided by the sub-tab: General = cards, Segment = grid, Affiliation = table.

13.1 General

Sub-tab with the Account fields shown as visual cards (switch, number, date, text, continuum, doughnut; see 13.4.1), with colour ranges. Editable values have a pencil and a Clear, in all sub-tabs, also the switch. Which cards are shown, in which order and whether they are editable is defined in Account_Insight_Card__mdt (see 13.4). The colours of the values are defined in Account_Insight_Range__mdt (optional, see 13.5).

13.2 Segment

Sub-tab with the Account Segment records of the account, shown as a grid: rows by Therapeutic Area, by Team, or by Therapeutic Area and Team, as defined in the metadata records (per CBU, Team and Record type), NOB / CL / Segment letter columns with descriptions, inline edit. In the default configuration NOB and CL are editable inline and Segment letter is read-only. Which columns are shown, in which order and whether they are editable is defined in Account_Insight_Card__mdt (see 13.4), so the default can be changed in the future by changing the metadata records only. The rows are the Account Segment records of the account, labelled by the row fields of the metadata (Grid_Row_Field_1__c, Grid_Row_Field_2__c). The colours of the values are defined in Account_Insight_Range__mdt (optional, see 13.5).

13.3 Affiliation

Shows the affiliations of the account, between HCP and HCP and between HCP and HCO: all the affiliation records where the opened account is From or To.

The sub-tab is a table with one row per affiliation. Which columns are shown, in which order and whether they are editable is defined in Account_Insight_Card__mdt (see 13.4), per CBU, Team and Record type, with the same 6-step resolution as item 3. A column is shown only if it has a record. The colours of the values are defined in Account_Insight_Range__mdt (optional, see 13.5).

  • An affiliation cannot exist without From and To. So every Affiliation configuration must contain a record for From and a record for To (they should have Sort_Order 1 and 2, so that they are the first two columns). They are normal records like all the others: if tomorrow From and To must be read-only, only the record changes (Editable__c = No), not the app.
  • + New affiliation button: the user picks From and To (both mandatory, and they must be different) and fills the other configured columns that are editable. The new affiliation is created as Soft.
  • Editable__c = Soft only means: editable only on affiliations whose Relationship type is Soft (Hard ones show a lock). Yes = editable on all, No = read-only.

13.5 Custom metadata Account_Insight_Range__mdt

Optional. Colour ranges of a card or column, up to 10 per card record. They apply only to the card record they point to. Ranges of the same record must not overlap. A range belongs to one card record only: if the same card exists in several configurations (for example DEFAULT and DE), each card record needs its own ranges.

FieldMandatoryDescription
LabelYesStandard field. Readable name of the range, in the format described in the Insight tab guide (section 2.0), e.g. Label of the card / Range 1.
DeveloperNameYesStandard field (Name in Setup). Unique name of the range: DeveloperName of the card + _ + number of the range (1 to 10), e.g. HCP_DE_ALL_ALL_GEN_BabiesPerYear_1. Same character rules as the card.
Insight_Card__cYesMetadata relationship to the card record (Account_Insight_Card__mdt). The record stores the DeveloperName of the card, e.g. HCP_DE_ALL_ALL_GEN_BabiesPerYear.
From_Value__c / To_Value__cFor numeric ranges (Number, Doughnut): at least one of the two. Blank for Text and ContinuumBoth limits are included. Blank From = no lower limit, blank To = no upper limit.
Values__cFor Text and Continuum ranges: yes. Blank for numeric rangesOne or more values separated by ; (e.g. "C;D").
Colour_Hex__cYesColour of the value, e.g. #2E7D32.

A range uses either the numeric limits or Values__c, never both. To switch a range off, delete the record.

13.5.1 What happens without ranges

Ranges are optional. If a card record has no range, or the value matches none of them, the value is still shown, with the default colours of the app, described below. No error is raised.

How it is shownDefault colour
Number, Text, Date, NameStandard text colour
SwitchOn = green, off = grey (ranges are never used)
DoughnutFilled part of the ring in the primary colour of the app (the colour of the selected tab and of the primary buttons), the rest of the ring in light grey
ContinuumAll the steps up to the current value in the primary colour of the app, the remaining steps empty (grey outline)
Metadata impact of the sub-tabs: Sub_Tab__c has three values, General / Segment / Affiliation, all in Account_Insight_Card__mdt, and it decides the layout (cards, grid, table).

Open points to confirm

  1. Source objects for Affiliation, Questionnaire and Sample: affiliation object, questionnaire assignment object, and where the product sample limit and delivered quantity are stored.
  2. Decision maker: editable by the rep on every affiliation. Confirm the field-level security and whether changes on Hard affiliations need an audit trail.
  3. Sample period: the limit is annual. Does the year mean the calendar year, or a fiscal year?
  4. Plan a call: does the calendar create a Pitcher call or a calendar event?
  5. Questionnaire Start: confirm it opens the existing Pitcher questionnaire, and whether mandatory ones must block anything (for example the call).
  6. Questionnaire and Sample tabs on HCO: both are shown on both pages. Confirm they are needed on HCO.
  7. Tab bar: HCP has 6 tabs and HCO 7. Confirm that the tab bar works well on iPad with this number of tabs.
  8. Affiliation columns: which columns does the business want per CBU and Team (Decision maker, Relationship type, Role, Start date, …)? Are the extra ones read-only, or editable (Editable__c)?
  9. Account Segment and Affiliation objects: the link to the opened account is taken from the object of the sub-tab. Confirm Account Segment has a single lookup to Account. For Affiliation both From and To point to Account, and the sub-tab shows the records where the opened account is either of them.
  10. Ranges: From and To limits are both included and ranges of the same record must not overlap. Confirm this rule.
  11. Default colours when no range is defined (13.5.1): confirm with the business.
  12. Invalid records: a card record whose Display_Type__c does not fit the field type is ignored (13.4.1). Confirm this behaviour, and whether an admin warning is needed.
  13. Account_Header_Field__mdt: the mandatory fields in the attached account header guide are proposed. Confirm in particular whether Source_Field__c is needed for Last Call, and the 4th field of the HCO line 2.
  14. Card groups: General shows a single list of cards in the order of Sort_Order__c, without section titles. Confirm the business does not need groups.
  15. Affiliation Soft / Hard: who creates Hard affiliations (integration, back office)? Users create only Soft ones.
