13. Insight tab Changed

The Insight tab has 5 sub-tabs, in this order: General, Segment, Affiliation, Questionnaire, Sample. The Related sub-tab was removed and is not included in the estimation and final design.

  • General, Segment and Affiliation are driven by the same custom metadata, Account_Insight_Card__mdt and Account_Insight_Range__mdt, with the same selection keys and the same 6-step resolution (see 13.6, 13.7 and the configuration guide in 13.8).
  • Questionnaire and Sample are fixed sub-tabs, always shown on the HCP and HCO page. They show standard data and need no metadata.

13.1 General

Sub-tab with the Account fields shown as visual cards (toggle, number, currency, date, text, continuum, doughnut), with colour ranges. Editable cards have a pencil / Clear and a toggle switch. Cards, sections and order are driven by Account_Insight_Card__mdt (Layout__c = Card) and Account_Insight_Range__mdt.

13.2 Segment

Sub-tab with the Account Segment records of the account, shown as a grid: rows by Therapeutic Area and/or Team depending on the CBU, NOB / CL / Segment letter columns with descriptions, inline edit. NOB and CL are editable inline; Segment letter is read-only New. Rows and columns are driven by Account_Insight_Card__mdt (Layout__c = Grid) and Account_Insight_Range__mdt.

13.3 Affiliation New

Shows the affiliations of the account, between HCP and HCP and between HCP and HCO: all the affiliation records where the opened account is From or To.

The sub-tab is a table. Each column is one record of Account_Insight_Card__mdt with Sub_Tab__c = Affiliation and Layout__c = Table. A column is shown only if it has a record: which columns, in which order, and whether they can be edited is decided per CBU, Team and Record type, with the same 6-step resolution as item 3.

13.8 Configuration guide: how to create the records

Field API names below are examples. Empty cells (—) mean the field is left blank because it does not apply. Rules:

  1. A configuration is the complete set of records for one CBU / Team / Record type. The app picks one step (item 3) and uses only its records, so a CBU that differs from DEFAULT needs the whole list, not only the differences.
  2. Create separate records for the HCP page and the HCO page (Page__c).
  3. Create records only for what has to be shown: if a field has no record, it is not displayed.
  4. Every Affiliation configuration needs a record for From and for To.
  5. All columns of one grid have the same Grid_Key__c and the same row fields.
  6. Ranges are created after the card, and point to it.
  7. To switch something off without losing it, untick Is_Active__c.

Explanation of custom metadata

Who sees which configuration (selection keys)

Each custom metadata record has 4 filters. Together they decide which users and accounts the record applies to:

  • Page: HCP page or HCO page.
  • CBU: the country code (e.g. DE, AT). Use DEFAULT for records that apply to every country without its own setup.
  • Team: the user's team (e.g. Adults, Paediatrics). Leave it empty to apply to all teams.
  • Record type: the account record type. Leave it empty to apply to all record types.

Only records with Is_Active = true are used.

How the app picks the configuration (resolution)

The app looks for the most specific configuration for the logged-in user and the opened account. It checks the steps below in order and stops at the first step that finds records:

  1. User's CBU + user's Team + account Record type
  2. User's CBU + user's Team
  3. User's CBU + account Record type
  4. User's CBU only
  5. DEFAULT + account Record type
  6. DEFAULT only

The whole configuration always comes from one step. The app never mixes steps: it never takes position 1 from one step and position 2 from another.

Open points to confirm New

  1. Source objects for Affiliation, Questionnaire and Sample: affiliation object, questionnaire assignment object, and where the product sample limit and delivered quantity are stored.
  2. Decision maker: editable by the rep on every affiliation. Confirm the field-level security and whether changes on Hard affiliations need an audit trail.
  3. Sample period: the limit is annual. Does the year mean the calendar year, or a fiscal year?
  4. Plan a call: does the calendar create a Pitcher call or a calendar event?
  5. Questionnaire Start: confirm it opens the existing Pitcher questionnaire, and whether mandatory ones must block anything (for example the call).
  6. Questionnaire and Sample on HCO: both are shown on both pages. Confirm they are needed on HCO.
  7. Affiliation columns: which columns does the business want per CBU and Team (Decision maker, Relationship type, Role, Start date, …)? Are the extra ones read-only, or editable (Is_Editable__c)?
  8. Account Segment and Affiliation objects: the link to the opened account is taken from the source object. Confirm Account Segment has a single lookup to Account. For Affiliation both From and To point to Account, and the sub-tab shows the records where the opened account is either of them.
  9. Ranges: From and To limits are both included. For decimals, ranges must not overlap. Confirm this rule.
  10. Affiliation Soft / Hard: who creates Hard affiliations (integration, back office)? In the mockup users create only Soft ones.
