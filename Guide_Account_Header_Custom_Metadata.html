Custom metadata guide: account header

Account page (HCP and HCO). Attachment to the Change Request "Account Page Redesign". Everything needed to understand and create the records of the account header.

1. How the custom metadata works

Who sees which configuration (selection keys)

Each custom metadata record of the account header has 4 filters. Together they decide which users and accounts the record applies to:

  • Page: HCP page or HCO page.
  • CBU: the country code (e.g. DE, AT). Use DEFAULT for records that apply to every country without its own setup.
  • Team: the user's team (e.g. Adults, Paediatrics). Use Default to apply to all teams.
  • Record type: the account record type. Use Default to apply to all record types.

Only records with Is_Active = true are used.

How the app picks the configuration (resolution)

The app looks for the most specific configuration for the logged-in user and the opened account. It checks the steps below in order and stops at the first step that finds records:

  1. User's CBU + user's Team + account Record type
  2. User's CBU + user's Team
  3. User's CBU + account Record type
  4. User's CBU only
  5. DEFAULT + account Record type
  6. DEFAULT only

The whole configuration always comes from one step. The app never mixes steps: it never takes position 1 from one step and position 2 from another.

2. Creating the records of the account header (Account_Header_Field__mdt)

The account header is the highlight panel at the top of the HCP and HCO page. Line 1 (name, chips, Start call, actions) is fixed. Line 2 has the 4 fixed fields defined by the global team. Line 3 has up to 4 fields that each CBU / Team / Record type can configure. Both lines are described by Account_Header_Field__mdt, one record per field.

2.1 Fields of Account_Header_Field__mdt

FieldMandatoryDescription
Page__cYesHCP / HCO.
Line__cYes2 = fixed line, global records (CBU DEFAULT) / 3 = configurable line.
CBU__cYesCountry code. DEFAULT as fallback for countries without their own setup (line 2 always uses DEFAULT).
Team__cYesTeam within the CBU, e.g. Adults, Paediatrics. Default = all teams.
Record_Type__cYesAccount record type. Default = all.
Position__cYes1 to 4. Position of the field in the line, from left to right.
Display_Type__cYesField / Link / Last Call. Field = value as text. Link = name of a related record, clickable (e.g. Workplace opens the HCO). Last Call = last call date and channel, which opens the Last Call Details popover.
Source_Object__cYesMetadata relationship to the object.
Source_Field__cYesMetadata relationship to the field.
Short_Label__cYesLabel shown in the panel.
Is_Active__cYes (checkbox, default ticked)Only active records are used.

Each record also has the standard Label and DeveloperName, which are mandatory.

2.2 Rules

  1. Line 2 is global: records with Line__c = 2, CBU__c = DEFAULT, Team__c = Default and Record_Type__c = Default. There is one set for the HCP page and one for the HCO page, maintained by the global team. Do not create other sets for line 2: it is the same for every country, so it does not use the resolution steps.
  2. Line 3 uses the 6-step resolution described in section 1. A configuration is the complete set of records (positions 1 to 4) for one CBU / Team / Record type: the app never takes position 1 from one step and position 2 from another.
  3. Create a DEFAULT set for the HCP page and for the HCO page first: it is the fallback for every country without its own setup.
  4. A CBU that differs from DEFAULT needs the whole list of positions, not only the position that changes.
  5. Position__c is unique within one configuration. A position without a record is empty.
  6. To switch a field off without losing it, untick Is_Active__c.
