Custom metadata configuration guide

Account page (HCP and HCO). Attachment to the Change Request "Account Page Redesign". Part 1: how the custom metadata works. Part 2: account header. Part 3: Insight tab.

Part 1. How the custom metadata works

Who sees which configuration (selection keys)

Each custom metadata record of the account page (account header and Insight tab) has 4 filters. Together they decide which users and accounts the record applies to:

  • Page: HCP page or HCO page.
  • CBU: the country code (e.g. DE, AT). Use DEFAULT for records that apply to every country without its own setup.
  • Team: the user's team (e.g. Adults, Paediatrics). Use Default to apply to all teams.
  • Record type: the account record type. Use Default to apply to all record types.

Only records with Is_Active = true are used.

How the app picks the configuration (resolution)

The app looks for the most specific configuration for the logged-in user and the opened account. It checks the steps below in order and stops at the first step that finds records:

  1. User's CBU + user's Team + account Record type
  2. User's CBU + user's Team
  3. User's CBU + account Record type
  4. User's CBU only
  5. DEFAULT + account Record type
  6. DEFAULT only

The whole configuration always comes from one step. The app never mixes steps: it never takes position 1 from one step and position 2 from another.

Part 2. Guide: account header (Account_Header_Field__mdt)

The account header is the highlight panel at the top of the HCP and HCO page. Line 1 (name, chips, Start call, actions) is fixed. Line 2 has the 4 fixed fields defined by the global team. Line 3 has up to 4 fields that each CBU / Team / Record type can configure. Both lines are described by Account_Header_Field__mdt, one record per field.

2.1 Fields of Account_Header_Field__mdt

FieldMandatoryDescription
Page__cYesHCP / HCO.
Line__cYes2 = fixed line, global records / 3 = configurable line.

Display_Type__cYesField / Link / Last Call. Field = value as text. Link = name of a related record, clickable (e.g. Workplace opens the HCO). Last Call = last call date and channel, which opens the Last Call Details popover.

Source_Field__cYesMetadata relationship to the field.
Short_Label__cYesLabel shown in the panel.
Is_Active__cYes (checkbox, default ticked)Only active records are used.

Each record also has the standard Label and DeveloperName, which are mandatory.

2.2 Rules

  1. Line 2 is global: records with Line__c = 2, CBU__c = GLOBAL, Team__c = Default and Record_Type__c = Default. There is one set for the HCP page and one for the HCO page. Line 2 does not use the resolution steps.
  2. Line 3 uses the 6-step resolution of part 1. A configuration is the complete set of records (positions 1 to 4) for one CBU / Team / Record type: the app never takes position 1 from one step and position 2 from another.
  3. Create a DEFAULT set for the HCP page and for the HCO page first: it is the fallback for every country without its own setup.
  4. A CBU that differs from DEFAULT needs the whole list of positions, not only the position that changes.
  5. Position__c is unique within one configuration. A position without a record is empty.
  6. To switch a field off without losing it, untick Is_Active__c.

Part 3. Guide: Insight tab (Account_Insight_Card__mdt and Account_Insight_Range__mdt)

The Insight tab has three sub-tabs, General (cards), Segment (grid) and Affiliation (table). They are described by two custom metadata types: Account_Insight_Card__mdt (one record for every card, grid column and table column) and Account_Insight_Range__mdt (optional, one record for every colour range). The meaning of each field, the mandatory fields and the display types are in sections 13.4 and 13.5 of the CR.

There are only two custom metadata types to fill: Account_Insight_Card__mdt (one record for every card, grid column and table column) and Account_Insight_Range__mdt (optional, one record for every colour range). The examples below always show all the fields of the type. A dash (—) means the field is left blank because it is optional or does not apply. Team__c and Record_Type__c are filled with Default when the record applies to all teams or all record types. Field API names are examples.

Rules:

  1. A configuration is the complete set of records for one CBU / Team / Record type. The app picks one step (part 1) and uses only its records, so a CBU that differs from DEFAULT needs the whole list, not only the differences.
  2. Create separate records for the HCP page and the HCO page (Page__c).
  3. Create records only for what has to be shown: if a field has no record, it is not displayed.
  4. Fill all the mandatory fields of the record (Mandatory column in sections 13.4 and 13.5 of the CR).
  5. Every Affiliation configuration needs a record for From and for To.
  6. All columns of the Segment grid have the same row fields (Grid_Row_Field_1__c, Grid_Row_Field_2__c).
  7. Ranges are created after the card record, and point to it.
  8. To switch something off without losing it, untick Is_Active__c.

3.1 General: cards (Sub_Tab__c = General)

One record per card, CBU DE; the last card is on the HCO page. Customer Status is a picklist shown as Continuum, GO Rating a checkbox shown as Switch, Nutricia Specialty a picklist shown as Text (dropdown when edited), Babies and Annual Revenue numbers (Annual Revenue is a currency field, so it shows the currency), Last Visit a date, Number of Beds a Doughnut with Max_Value__c. Card_Label__c is filled only for Babies, to override the label of the field. A multipicklist field would also use Text.

3.2 Segment: grid (Sub_Tab__c = Segment)

The grid has one record per column: here NOB, CL and Segment letter. The rows are the Account Segment records of the opened account, one row per record. The two row fields say how each row is named: Grid_Row_Field_1__c (mandatory) and Grid_Row_Field_2__c (optional, shown as a chip). They are chosen per configuration (CBU, Team, Record type), so the same grid can be by Therapeutic Area, by Team, or by Therapeutic Area and Team. Rows are sorted by the first row field and then by the second. Use the same row fields on all the column records of a configuration. The three cases below show all the fields of the records. Segment letter has Editable__c = No, so it is read-only. The order of the CL steps (1 to 5) and of the letters (D to A) is the order of the picklist values on the field.
